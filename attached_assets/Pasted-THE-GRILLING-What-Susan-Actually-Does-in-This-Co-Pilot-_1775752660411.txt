THE GRILLING
What Susan Actually Does in This "Co-Pilot"
Manually opens Settings, types in 12 different IDs and emails

Manually clicks "Generate Report"

Manually acknowledges the staleness warning

Manually clicks "Send to PI"

Manually waits for PI to review

Manually clicks "Mark as PI Approved"

Manually clicks "Mark Final + Update Call"

That's 7 manual steps. The only "automated" thing is the nag email every 4 hours — and even that requires manually setting up a Scheduled Deployment.

This is not a co-pilot. This is a dashboard with API calls behind buttons.

Where's the Agentic Flow?
A real co-pilot would:

Detect that it's the last week of the month and Susan hasn't generated a report yet → proactively suggest: "Monthly sponsor report is due in 3 days. Generate now?"

Automatically check data freshness before Susan even thinks about it — not wait for her to click a button and then show a warning

Watch the Google Doc for the PI's cursor activity or comments → detect when the PI has finished reviewing → auto-prompt Susan: "PI left 2 comments and hasn't edited in 30 minutes. Ready to mark approved?"

Monitor the Notion AE log in real-time → if a Grade 3+ AE lands mid-month, alert Susan immediately: "New Grade 3 AE reported. This may need to go in an interim safety report to the sponsor."

Pre-fill Settings by scanning Susan's connected Google Drive for sheets that match the enrollment format, Notion for databases with the right property schemas — not make her paste 12 IDs by hand

Chain the entire workflow end-to-end: detect trigger → generate → check → send → nag → detect approval → finalize → update calendar. Susan's role should be approval gates only, not button-pressing at every step.

Where Are the Tests?
The spec says nothing about testing. No unit tests for the generation flow. No integration tests for the API routes. No end-to-end test that runs Generate → Send → Approve → Finalize and confirms the Google Doc exists, the email was sent, and the calendar event was updated.

If this were handed to Susan right now and any API call failed mid-flow, she'd see a 503 error and have no idea what to do. There's no retry logic, no partial recovery, no "step 6 of 9 failed, here's what succeeded and here's what you need to fix."

Phase 3: Make it testable (before demo)

The spec is excellent. The architecture is clean. The data contracts are precise. But right now this is a well-documented manual tool, not a co-pilot. The "co" in co-pilot means the system does work autonomously and Susan supervises — not that Susan does all the work and the system holds the clipboard.
